# Wayfarer Class Bible — Approved Implementation Sequencing Policy
Approved: 20 October 2026
Status: binding production sequencing rule, not a rewrite of class design canon.

## Core production rule
Develop and polish classes in small batches instead of mass-implementing all fourteen at once. Preserve all fourteen existing class specifications and the 13×14 race/class compatibility audit. All fourteen classes must be fully integrated, balanced, playtested and polished at initial release; batching is a development process, not phased commercial delivery.

## First validation batch
1. **Vanguard — Melee combat foundation:** Movement, attacking, blocks, perfect parries, stamina, weapon combos, finishers, enemy posture/reactions, defensive and offensive builds.
2. **Lightkeeper — Healing and support foundation:** Active healing, hit-point control, buffs/support, melee/wand combat, robust solo viability, usefulness to parties.
3. **Spellwright — Spellcasting foundation:** Casting while walking/aiming, targeting, spell visuals, animation integration, magic feedback and progression. Ordinary movement while casting is retained as universal caster canon.

## Required acceptance gates
Each class must be demonstrably:
- **Fun:** satisfying repeatedly in actual gameplay, not merely functional;
- **Distinct:** strong identifiable play loop and meaningful identity;
- **Solo viable:** able to handle appropriate challenges alone;
- **Party valuable:** offers useful team roles and interactions;
- **Balanced:** strengths, weaknesses, counterplay and resource tradeoffs; balance does not mean identical damage or mirrored kits.

Test each class in comparable controlled encounters: single foes, enemy groups, ranged and spellcasting foes, elites, boss mechanics, survival and resource pressure, and solo/cooperative play. Check controls, animations, responsiveness, clear times, survival, cooldown/ability usage, and regressions. Record results and needed changes before approving an implementation batch.

## Systems and iteration
Test class switching in the foundational batch. Every playable race can use every class. Each class retains its own level and progression; verify abilities, resources, equipment, saved state, and UI when switching. Prototype tuning values (frames, resource costs, cooldowns, coefficients, universal input-slot counts) remain provisional until balanced and tested.

No subsequent batch order is canonized yet: select following classes and pairings after evidence from the first three. Preserve complete initial-release vision, including all fourteen classes, and do not treat unfinished class features as commercially releasable content.
